# A landing page with a live code cell

Status: built with this note, 2026-10-05. The decisions below are what the page does;
any of them can change in review.

Cho asked for what some projects have on their front page: a code cell a reader can
edit and run in the browser, with nothing installed. This note says what the page is,
how it runs Python, what it costs the reader, and why the listening gallery stays where
it is.

## What a reader sees

`https://choyun1.github.io/sonore/` has had no page: the Pages site serves `docs/`,
which held the gallery and the API reference but no `index.html`. The new page is the
README's opening paragraph, links to the gallery, the Colab tutorial, the API reference
and GitHub, and one editable cell. The cell is the tutorial's first example: a tone in
noise, its overview, and a player.

Run (or Ctrl+Enter) shows what a notebook would, in the same order: printed text, an
error if there is one, a player for a `Sound` on the last line (or one per sound in a
list or tuple), then every figure the cell made. The player follows the rule
`Sound._repr_html_` follows: the sound plays at its true level, and a sound peaking
above full scale gets a note instead of a player. The cells share one namespace, as a
notebook kernel's do.

## How it runs

The page runs CPython compiled to WebAssembly, [Pyodide](https://pyodide.org), in a
web worker so the page stays responsive while Python loads. Pyodide brings its own
builds of numpy, scipy, matplotlib and soundfile; sonore is a pure-Python wheel, which
micropip installs from PyPI. Files:

- `docs/index.html`: the page, hand-written, with the gallery's colours and fonts.
- `docs/try/worker.js`: loads Pyodide and sonore on the first Run, then runs cells.
- `docs/try/runner.py`: the Python side, which runs a cell and turns what it shows into
  text, WAV bytes and PNGs. It is plain Python, so `tests/test_landing_page.py` runs it
  under CPython on the page's own example.

## Decisions

**D1. A new page at the site root; the gallery stays at `/gallery/`.** The root was
empty, so nothing moves and no link breaks. The gallery is generated by
`docs/gallery/build.py` and coupled to the tests and checkers; moving it would buy
nothing the new page needs. The landing page links to the gallery; the gallery's own
navigation is unchanged for now. A later step could give gallery cells their own Run
buttons through the same worker (not done here).

**D2. Pyodide from its CDN (jsDelivr), pinned to 314.0.7.** The full Pyodide release is
337 MB, too much to commit or deploy; the CDN serves the same files. Pinning means a
new Pyodide (new numpy, scipy, matplotlib) can't change the page without a commit.
Pyodide 314 runs only in a module worker, which `worker.js` is.

**D3. sonore from PyPI, unpinned.** The page installs the latest release, so it never
points at a version PyPI doesn't have yet (the version in `__init__.py` is set before
the release is uploaded, see `docs/releasing.md`). The example is tested against the
repository, so a release that breaks it fails the test first.

**D4. Python loads on the first Run, not when the page opens.** It is a 35 MB download;
a reader who only reads the page shouldn't pay for it. The status line says what is
loading.

**D5. A plain text area, no code editor library.** No syntax colours, but no extra
download or script from another site, and the browser's own undo, find and
accessibility work. Tab moves focus as everywhere else on the page rather than
indenting, so a keyboard user can leave the cell.

**D6. One short example, from the tutorial's first section.** It runs in 1.5 to 1.7 s
in the browser (measured below). Slower things (texture synthesis, the moving talker)
stay in the Colab tutorial and the gallery, where the reader expects to wait.

**D7. Tracebacks show only the cell's own frames,** with the cell's lines quoted, so an
error reads like one in a notebook rather than pointing into the runner.

**D8. No browser test in CI.** CI would need the CDN and a headless browser on every
run. The test runs the runner and the example under CPython and checks that the worker
loads every dependency in `pyproject.toml`; the page itself was checked in headless
Chromium as described below.

## Measured

On the cloud container (4 CPUs), 2026-10-04 and 2026-10-05:

- Headless Chromium, Pyodide files served from local disk (the container can't reach
  the CDN) and sonore 0.5.0 fetched from PyPI: first Run ready in 15 to 16 s, the
  example then ran in 1.5 to 1.7 s, the player reported a duration of 0.5 s. Later
  runs of small cells took under 0.1 s.
- Download size, from the Pyodide 314.0.7 release files: core 13.5 MB (6.3 MB
  gzipped), the 17 packages sonore needs 28.3 MB (scipy 14.0, matplotlib 7.0, numpy
  3.0), the sonore wheel 0.2 MB. About 35 MB in all.
- The whole Colab tutorial's 22 code cells also run under Pyodide with sonore 0.4.0
  and 0.5.0 (downloads copied in, HRIRs replaced as in `tests/test_notebook.py`):
  141 s and 95 s on two runs, against 76 s in CPython 3.11 on the same machine.

Estimates, not measured: the download time on a reader's connection (35 MB is a few
seconds on fast broadband, much longer on a phone), and the page's "around half a
minute" for a first run. Browsers cache the files, so a second visit skips the download.

## What does not work in the page

- `so.load_hrirs` downloads from sofacoustics.org with `urllib`, which Pyodide does not
  support without the `pyodide-http` package, and whether that site allows reads from
  other origins is untested. The HRIR terms allow only the SOFA project's copy, so
  the page can't host one.
- Files from the repository (the speech sample, the textures) are reachable with
  `pyodide.http.pyfetch`, not `urllib`; the example doesn't need them.
- `Sound.play()` (sounddevice) and anything multi-threaded don't exist in the browser.
